## Calls made

- **Survivor per fold.** The plumbing precedent folds the copy into the id of the primary set (board over driver copy; sealed spark over upcoming twin). The 27-x/28-x/29-x majors are the primary tier, so the major survives every pair: R6 into 27-6, E12 into 27-4, E17 into 29-2, E26 into 29-1. The fold reuses `fold_all` from `earth2/plumbing_2026-11-25.py` (loaded, not copied), then keeps the copy's full record under `folded_from` and carries onto the survivor any model field it lacked (curve, settlement test, next_watch, what_changed, if_it_fires, hit, board_arm).
- **Survivor odds rule.** The survivor keeps its own odds_now (plumbing precedent); the copy's odds, curve, window and odds_history stay on the survivor under `folded_from`. apply_rebase.py checks odds_now is unchanged on every surviving node before it writes. 27-6 and 27-4 are then re-rated by updates.json.
- **Odds stamp.** Removing four nodes changes the stamp without any odds edit, so apply_rebase.py resets it and logs a `kind: restamp` entry in cascade_log (the same record `cascade.py --restamp` writes) with the reason.
- **Curve rule.** Deadline = window_end. The deadline value is the curve point in that month on or before it; else the linear interpolation; if the deadline is before every point, the first point (after a one-day event the cumulative curve equals the final odds); if after every point, a point is added at the deadline. All other points are scaled by the ratio of the nearest anchor (the deadline or an explicit proposal point). Cumulative curves are kept non-decreasing; the three changed curves that fall by design (PG5, PG9, R4: 'condition still holds' nodes) keep their shape. Every changed point is held to 1..99. Nulls stay null. Applied to every live curve, because cascade runs move odds_now and never odds_by, so 75 curves had drifted.
- **Rebase mode.** `--rebase` forces 0 hops, needs `--updates` with no `--set`, `--reason` or `--date`, refuses rows whose reason does not start with REBASE or that lack a source, tags the log entry `kind: rebase`, refuses a second rebase, writes no collisions queue (level corrections are not collisions) and leaves status as it was (a level correction is not news). All six refusals were tested.
- **Re-rates against later reads.** Every "Now" in list B matches the graph today (or matches the folded copy's curve), so no proposal was dropped for a later read. Where a proposal names a horizon that is not the node's deadline, the number went onto the curve and odds_now stayed (D6, C4, C8, E31, and E26 on 29-1).
